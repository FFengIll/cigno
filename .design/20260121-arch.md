## Project Overview

Cigno is a **daemonless container image assembly builder**: it assembles
images from prebuilt artifacts and component images using pure OCI registry
operations (via `crane` from go-containerregistry) — no Docker daemon, no
privileged runtime, no overlay filesystem. It never executes commands:
`RUN` is rejected with guidance.

Key properties:
- Assembly-only: COPY/ADD + config instructions, Dockerfile semantics aligned
  with the docker reference and locked by hermetic tests
- Layer diffing (`COPY --from=<image>`): only diff layers are transferred,
  the base image is never re-pulled in full
- Single static binary, stateless, CI/sandbox friendly
- Embedded registry v2 server for local cache / push targets
- Output: push to a registry, or a docker-loadable tar

## Core Components

### 1. Engine (`pkg/engine.go`)

**BuildEngine** orchestrates a build:
- `BuildContext`: map of named contexts (image-ref, tarball-ref, path-ref)
  — serves both `FROM` and `COPY --from=<name>`
- `GlobalArg` / `LocalArgs`: ARG scopes; global defaults inherited by
  in-stage `ARG KEY` redeclarations
- `Env`: per-stage environment; expansion order is ENV → local ARG →
  global ARG (docker precedence)
- `LayerType`: media type for emitted layers (Docker/OCI)
- `stages`: built stages recorded for `COPY --from=<stage>` (path-level)

### 2. Build Process (`pkg/build.go`)

1. Parse Dockerfile into stages (buildkit parser)
2. For each stage:
   - Resolve base image: registry ref (disk-cached), tarball, folder,
     `scratch` (defaults to amd64/linux)
   - Process instructions:
     - **COPY/ADD**: local context → tarball layer; `--from=<stage>` →
       path-level copy out of the stage's built filesystem;
       `--from=<image>` → layer-diff rebase (verbatim layers)
     - **ADD**: + content-detected archive extraction (local only;
       remote URLs are never decompressed)
     - **Config commands**: mutate image config + history
     - **RUN**: hard error with guidance
   - Validate first (`validate.go`); unknown instructions warn + skip
     (`SHELL`, `HEALTHCHECK`, `STOPSIGNAL`, `ONBUILD`, `MAINTAINER`)
3. Apply build options (push, save to tar, print history)

### 3. Copy Handling (`pkg/copy.go`)

- Local sources: wildcards (`filepath.Match`), `.dockerignore`, directory
  semantics (dir → contents under dest; multi-source → dest is dir),
  `../`-stripping, `--chown`/`--chmod`, env/arg expansion in paths
- `COPY --from=<stage>`: path-level copy from a previously built stage
  (docker semantics)
- `COPY --from=<image>`: **rebase** — `subBaseImage()` computes diff layers
  against the source image's base (from annotations) and appends them
  verbatim; the base is never re-pulled

### 4. Embedded Registry (`pkg/registry/`)

Registry v2 API on stdlib `net/http` with filesystem storage: blob upload
(init/chunked/monolithic/finish + sha256 verification), manifest
PUT/GET/DELETE, tag list. `cigno registry start/stop/status`; localhost
refs automatically use plain HTTP.

### 5. Cache (`pkg/cache/`)

Base images cached on disk (`~/.cigno/cache/`); `cigno cache list/clear`;
`--no-cache` disables it.

### 6. CLI (`cmd/`)

- `cigno build`: `--file` (required), `--tag`, `--push`, `--output-file`,
  `--build-arg`, `--context`, `--no-cache`, `--validate` (parse-only),
  `--env-strategy keep|refresh`, plus legacy `--image-base/--tarball/--folder`
- `cigno registry start [--addr] [--storage]` / `stop` / `status`
- `cigno cache list` / `clear`
- `cigno --version`

## Key Design Patterns

1. **Option Pattern**: `BuildOption` for post-build actions
2. **Functional Options**: `TarOption` for tarball transformations
3. **Layer Diffing**: `subBaseImage()` computes deltas for rebase
4. **Annotation Tracking**: base image digest/name stored in OCI annotations
5. **Hermetic testing**: every build test runs against the in-process
   embedded registry — no network, no docker (`go test ./...`)
